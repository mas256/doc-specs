# 文書作成規格 第4版 書く手順 工程2:草案

この工程の目的は、執筆者が、要件定義書・author-style・構成案だけから、論点・順序・詳しさを推測せずに本文を書ける箇条書きを、依頼者と共同で作ることである。本文の文章は、この工程では書かない。

## O1 始め方

- O1.0 構成案の材料は、承認済みの要件定義書と、壁打ち(中身)で依頼者が取捨を承認した中身(phase-0-discussion.md Z5.4)である。
- O1.1 依頼者が箇条書きを出した場合は、それを出発点にする。W5.3に従って批評し、断りなく並べ替えた版で置き換えない(W5.4)。
- O1.2 箇条書きが出ていない場合は、依頼者がまず「必ず伝えたいこと」を挙げるか、AIが要件定義書からたたき台を作るかを尋ねる。AIが作る場合も、構成案は承認までは草案である(common.md N7.5)。要件定義書と、壁打ち(中身)で承認された中身にない項目が要ると判断した場合は、壁打ち(中身)へ戻して決める(common.md N6.2)。

## O2 構成案の組み立て

- O2.1 階層は、文書全体 → 章・部 → 節・項・話題 → 項目(箇条書きの1行)とする。文書に存在しない階層は作らない。
- O2.2 1つの項目は、読者に起こす変化1つに当てる(本文では数文単位、目安は1段落になる)。項目は、本文で述べる順に並べる。
- O2.3 文書全体と、各章・部、各節・項・話題に、変化(N1.2)を一文で書く。下位の単位の変化は、上位の単位の変化に含まれるようにする。
- O2.4 項目には、述べる内容を短い句か文で書く。本文の文章にしない(表現は工程3で決める)。ただし、依頼者が指定した言い回し・定義の文面・式は、そのまま書き留める。
  - 項目は、話題の名前ではなく、述べる内容で書く。執筆者が、その1行から、何を主張し何を示すのかを推測せずに読み取れるようにする。
  - 悪い例:「特性方程式について」(何を述べるのかが分からない)
  - 良い例:「定数項を消すために、両辺から同じ数 $\alpha$ を引く。$\alpha$ は $\alpha = p\alpha + q$ を満たす数に選ぶ」〔式:$a_{n+1} - \alpha = p(a_n - \alpha)$〕
- O2.5 導出を含む文書では、結論の式と、導出の道筋(どの事実から、どの操作で進むか)を構成案に書く。導出の道筋を工程3で初めて決めることはしない。
- O2.6 注記は、決まっている場合と必要な場合にだけ付ける。すべての項目に付けることを求めない。

| 注記 | 書くこと |
| --- | --- |
| 〔詳しさ〕 | 詳しく/簡潔に/触れるだけ |
| 〔強調〕 | 強調する点 |
| 〔式〕〔図〕〔表〕〔例〕 | 使うものと、その内容 |
| 〔始め方〕〔締め方〕 | その単位の入り方・終わり方の指定 |
| 〔脇道〕 | つながる先と、そこで重要である理由 |
| 〔前提〕 | この項目が使う既出の事柄のうち、離れた位置にあるもの |
| 〔任せる〕 | 依頼者が、執筆者に任せると明示した事項 |
| 〔未決〕 | 決まっていない事項 |

- O2.7 〔詳しさ〕のない項目は、想定読者が飛躍(common.md N1.5)も負担もなく次の項目へ進める詳しさで書くものとして扱う。読者が1回の操作で越えられる過程、前に見た一歩、author-style が省略を許す議論は、省略(N1.20)してよい。

- O2.8 組み立ての順:AIがたたき台を作る場合も、依頼者の箇条書きを整える場合も、次の順で進める。
  1. 文書全体の変化を、要件定義書の「読後に期待すること」から書く。
  2. 章・部の変化を並べる。合わせると全体の変化になるか、欠けている変化がないかを確かめる。
  3. 章ごとに、章の変化に読者が達するために必要な理解を、到達点から始めの状態(想定読者の扱えるもの)へ向かって逆にたどって挙げる。扱えない形が要る場合は、事前説明の項目を置く。
  4. 挙げた理解を、始めの状態から到達点への順に並べ直し、節・項・話題に分ける。位置は common.md N11 に従う(変化が複数あるときは冒頭の構えで全部を渡す、前提条件は使う前に示す、など)。
  5. 節ごとに、項目(1行に変化1つ)に落とす。
  6. 決まっている注記を付ける。決まっていない事項は〔未決〕とする。
- O2.9 複数の構成案は、必要に応じて作る(必須にしない)。作るかどうかは、要件による。

## O3 構成案の確かめ方

構成案を批評するとき(W5.3)と、自分でたたき台を作るときは、次を確かめる。問題を見つけた場合、内容に関わる直し方は案として示し、依頼者が決める。

- O3.1 必要性:各章・節・項目が、上位の単位の変化に結び付いているか(J4)。除いても読後に期待することに届く項目は、省略・移す・削除のどれにするかを依頼者に尋ねる(common.md N9.3)。
- O3.2 順序と前提:各項目が使う語・定義・事実・形が、それより前の項目か、想定読者の扱えるものにあるか。ない場合は、順序を変える案か、前提の項目を足す案を示す。
- O3.3 道筋と論証:隣り合う項目の間に飛躍(common.md N1.5)がないか。主張を含む場合は、論証の穴(N1.21 の3)がないかも確かめる(N9.5)。欠けた中間の項目は、案として示すか、質問する。
- O3.4 重複と用語:意図した言い換え・再提示を除き、同じ内容の項目が繰り返されていないか。定義や名前を与える用語・記号は、構成案で一つの形に決め、author-style の用語・表記表(固定する用語・記号)への追記案にまとめる。似ているが意味の違う語を使い分ける場合は、その違いを「意図して使い分ける対」への追記案に書く。
- O3.5 分量の配分:項目の数と詳しさの配分が、依頼者の示した重要度に見合うか。重要度をAIの見立てで決めない。
- O3.6 正確性:項目に書かれた主張・式・数値・引用を、common.md N8.4に従って確かめる。
- O3.7 構成の別案:文書全体(章ごとに進める場合はその章)の順序について、現行とは別の構成を少なくとも1つ検討する。想定読者の負担が現行より減ると判断した場合だけ、理由を添えて示す。
- O3.8 構成の型(結論→根拠→具体例→結論、起承転結など)に当てはめること自体を目的にしない。想定読者が自然に追える順序を基準にする。要件定義書の項目(読後に期待することの要素、必ず入れる論点)を、そのまま章・節・段落の並びにしない。並びは、O2.8 で逆にたどった理解と、想定読者が追える順で決める。

## O4 構成案の書式と承認

- O4.1 次の書式で書く。

```text
# 構成案:[文書名](版・日付)
全体の変化:…
構成:1 [章の仮題]/2 [章の仮題]/…

## 1 [章の仮題]
変化:…

### 1.1 [節の仮題]
変化:…
- 項目 〔詳しさ:詳しく〕
- 項目 〔例:…〕
- 項目 〔脇道:…につながる。理由は…〕
```

- O4.2 承認を求める前に、〔未決〕を一覧にして示し、依頼者に決めてもらう。用語・表記表への追記案(O3.4)も、あわせて示す(N3.7)。〔未決〕が残った構成案で、承認を求めない。依頼者が執筆者に任せると答えた事項は、〔任せる〕に改める。
- O4.3 構成案を示して承認を求める。承認を得たら、工程3へ進む。
