# 文書作成規格 第4版 書く手順 工程0:壁打ち(目的)と壁打ち(中身)

工程0には2つの壁打ちがある(common.md N6.1)。壁打ち(目的)は、何を書くかがまだ固まっていない依頼者と話しながら、目的(誰に、何を伝えたいか)を広げ、要件定義(工程1)の材料を集める。壁打ち(中身)は、要件定義の後に、題材・切り口・主張の核を広げ、誤りと反論を確かめ、依頼者の取捨を受ける。Z1〜Z4 は壁打ち(目的)の定め、Z5 は壁打ち(中身)の定めである。壁打ち(目的)は内容を膨らませる段階なので、定めは少なくしてある。

## Z1 進め方

- Z1.1 依頼者の言葉を引き出すところから始める。どんな読者のどんな場面を思い浮かべているか、書こうと思ったきっかけは何か、何が気になっているか、を尋ねる。
- Z1.2 話の向きと深さは、依頼者に合わせる。質問を重要な事項だけに絞る定め(W5.1)、質問を1回にまとめる定め(W5.2)、承認を待つ定め(W2.1)は、壁打ち(目的)では適用しない(壁打ち(中身)には適用する。Z5)。
- Z1.3 依頼者の案への批評(W5.3)は、求められたときと、案の弱点が後の工程に響くと考えたときに行う。同調を目的にしない点(common.md N8.6)は、この工程でも変わらない。

## Z2 AIの案

- Z2.1 論点、切り口、反論、たとえ、構成の案を、広く出してよい。依頼者が挙げていない論点を出すことも妨げない。
- Z2.2 AIが出した案は、壁打ちメモに「AI」と記して、依頼者の案と区別する。発言のたびに「AI提案」と断る必要はない。
- Z2.3 AIの案が文書の要件に入るのは、工程1で依頼者が承認したものだけである(common.md N7.5)。この工程で依頼者が「採る」と言った案も、工程1でもう一度確かめる。

## Z3 下調べ

- Z3.1 下調べは、広く浅く行う。どんな論点があるか、既にどんな議論や資料があるかを見渡すことが目的である。どこまで深く調べるかは、依頼者の指示に従う。指示がなければ、深追いしない。
- Z3.2 調べた事柄には、出典を添える。出典のない事柄は、AIの記憶によるものと明記する。
- Z3.3 この工程で挙がった事実・数値・引用は、すべて未確認として扱う。本文に使う前に、common.md N8.4に従って調べ直す。

## Z4 壁打ちメモと終わり方

- Z4.1 成果物は、壁打ちメモ1つである。話が進むたびに書き足す。書式は次のとおりとし、項目は増やしてよい。

```text
# 壁打ちメモ:[仮の題](日付)
1. 出た論点:論点|誰の案か(依頼者/AI)|依頼者の反応(採る/捨てる/保留/未確認)
2. 読者と目的について分かったこと(依頼者の言葉で)
3. 調べた事柄:事柄|出典|未確認
4. まだ答えの出ていない問い
```

- Z4.2 工程1へ移るのは、依頼者が移ると言ったときである。AIは、「想定読者」と「読後に期待すること」(R2.2の必須の2項目)を埋める材料がそろったと見たときに、移ることを提案してよい。
- Z4.3 承認は求めない。壁打ちメモは、工程1の資料になる(R1.1)。執筆と改稿の担当には渡さない(W2.9)。

## Z5 壁打ち(中身)

要件定義の後に、承認された要件定義書から、文書に入れる中身(題材、切り口、主張の核)を決める。中身が決まっていれば飛ばす(common.md N6.1)。中身を探すうちに目的を変えたくなった場合は、要件定義へ戻る。

- Z5.1 手順(common.md N6.4):
  1. 観点を出す:読後に期待することから、どんな性質の題材が要るかを3〜5つ挙げる。依頼者が持ち込んだ視点は、切り口の候補の一つとして扱う。
  2. 題材を出す:観点ごとに、当てはまる題材を10ほど挙げる。
  3. 切り口を作る:書き方の向き(一文)と、それを支える題材の束を、2〜3作る。要件から一歩出た案(問いの読み替え、題材の元の仕組みの分析、意外な具体例)も、ここで作ってよい。
  4. 確かめる(依頼者に示す前に、すべての候補に当てる。選んだ候補にだけ当てない):
     - 題材の事実・数学の誤り:検証担当に確かめさせる。誤りのある題材は示さない。
     - 主張の核の候補が反論(common.md N1.21)に耐えるか:ロールモデルとして読む担当に、反例と別の説明を出させる。耐えない候補は、その理由を添えて示す。
     - 説明の費用:読者が扱えない形を使う題材は、事前説明に要る字数を見積もり、分量の上限と比べる。
     - 親近感と新しさ:ロールモデルにとって身近な事柄か、そこに加わる解釈が読者にとって新しいか。
  5. 示す:切り口ごとに、主軸の題材と補強の題材、確かめた結果を並べて示し、依頼者の取捨を受ける。使わない題材のうち価値のあるものは、移す(余談、注釈)候補として残す。
- Z5.2 数は文書の大きさで増減してよい。小さい文書では、観点と切り口を少なくし、題材の数も減らす。
- Z5.3 担当とモデル:観点と切り口は agents/writing-angles(sonnet の high)、題材は agents/writing-topics(haiku の high)、ロールモデルとして読む担当は agents/writing-rolemodel(sonnet の medium)を使う(common.md N12)。題材の誤りは、agents/review-checker を要求つきで起動して確かめる(W2.11)。担当に渡すのは、要件定義書と、その段の作業パケット(切り口の段では題材の一覧、ロールモデルの段ではロールモデルと候補)だけにする。依頼者との議論の経過は渡さない。担当が出したものを束ね、説明の費用を見積もり、依頼者に示すのは窓口である。
- Z5.4 成果物は、依頼者が取捨を承認した中身(使う題材と切り口、主張の核、移す候補)である。草案(工程2)は、これを正本として構成案を作る。
