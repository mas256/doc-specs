# 文書作成規格 第5版 書く手順 壁打ち(要件定義書と author-style を作るまで)

壁打ちは、窓口(主の会話)が依頼者と議論する段である。ねらいは二つある。何を書くか(読者、読後に期待すること、切り口)を定めること。依頼者がその事柄への理解を深め、後の段の監督の質を上げること。壁打ちは、依頼者が「終える」と言うまで続ける。終えた後に、要件定義書と author-style を作って承認を得る。Z は議論の定め、R は終えた後に作るものの定めである。

## Z1 進め方

- Z1.0 最初の発言で、次の3つを伝える。これから壁打ちを行うこと。依頼者が終えると言うまで続けること。終えた後に、その議論から author-style と要件定義書を作り、承認を求めること。
- Z1.1 依頼者の言葉を引き出すところから始める。依頼を言い直し(AIがどう理解したか)、どんな読者のどんな場面を思い浮かべているか、書こうと思ったきっかけは何か、何が気になっているか、を尋ねる。言い直しは、AIが依頼を理解するためのもので、要件定義書の欄を埋めるためのものではない。
- Z1.2 話の向きと深さは、依頼者に合わせる。尋ねる事項を絞る定め(W5.1)と、尋ねることをまとめる定め(W5.2)は、壁打ちの議論には当てはめない。
- Z1.3 依頼者の案には、弱点が後の段に響くと考えたときに、根拠を添えて批評する(W5.3)。同調を目的にしない(common.md N8.6)。読者に届くか、範囲と分量に収まるかも、議論の中で確かめる。

## Z2 AIの案

- Z2.1 論点、切り口、反論、たとえ、構成の案を、広く出してよい。依頼者が挙げていない論点を出すことも妨げない。
- Z2.2 壁打ちメモの「誰の案か」には、依頼者が出した論点なら「依頼者」、AIが出した論点なら「AI」と書く(Z4.1)。誰が出したかの記録であり、採否は「依頼者の反応」に書く。
- Z2.4 切り口の案:題に関わる話題・事実・見方を、とても広く、深くしないで調べ(Z3)、切り口の案(着眼点、主張の一文、主な題材。common.md N1.23)を複数出す。依頼者の見方も、切り口の一つとして並べる。議論の中で、混ぜる・足す・捨てるを繰り返し、依頼者が切り口を決める。
- Z2.3 AIの案が要件定義書に入るのは、依頼者が承認したものだけである(common.md N7.5)。

## Z3 調べ物

- Z3.1 調べ物は、広く浅く行う。どんな話題・見方があるか、既にどんな議論や資料があるかを見渡すことが目的である(common.md N8.10)。どこまで深く調べるかは、依頼者の指示に従う。指示がなければ、深追いしない。議論の中で要れば、その場で調べ直す。
- Z3.2 調べた事柄には、出典を添える。出典のない事柄は、AIの記憶によるものと明記する。
- Z3.3 壁打ちで挙がった事実・数値・引用は、すべて未確認として扱う。本文に使う前に、論点案の作成で確かめ直す(Z5.3)。

## Z4 壁打ちメモと終わり方

- Z4.1 壁打ちメモを一つ持ち、話が進むたびに書き足す。書式は次のとおりとし、部は増やしてよい。
  - 一つの論点・切り口・事柄ごとに、「名前: 値」を1行ずつ書く。欄の名前は省かない。
  - 依頼者の反応の「保留」は、依頼者が「後で決める」と答えたもの、「未決」は、まだ答えがないものである。

```text
# 壁打ちメモ:[仮の題](日付)

読者と目的について分かったこと:
- (依頼者の言葉で)

切り口の案:
- 着眼点: (一文)
  主張: (一文)
  主な題材: (句で並べる)
  誰の案か: 依頼者/AI
  依頼者の反応: 採る/捨てる/保留/未決

出た論点:
- 論点: (一文)
  誰の案か: 依頼者/AI
  依頼者の反応: 採る/捨てる/保留/未決

調べた事柄:
- 事柄: (一文)
  出典: (書名やURL。なければ「なし」)
  確かめたか: 確認済/未確認

選んだ理由・捨てた理由:
- (依頼者の言葉で。部品の材料になる。common.md N3.8)

まだ答えの出ていない問い:
- (一文)
```

- Z4.2 終える:壁打ちを終えるのは、依頼者が終えると言ったときである。AIは、読者、読後に期待すること、切り口を書ける材料がそろったと見たときに、終えることを提案してよい。依頼者が壁打ちを「任せる」と言った場合は、窓口が切り口の案から一つを推奨案として選び、R に従って作って、承認を求める。
- Z4.3 壁打ちメモは、要件定義書と author-style の材料であり、論点案の作成で企画の担当に渡す。執筆と改稿の担当には渡さない(W2.9)。

## R2 要件定義書の欄

- R2.1 壁打ちメモから、次の欄を書く(書式は handoff.md N5.1)。

| 欄 | 書けたと言える基準 |
| --- | --- |
| 読者 | 誰か(立場、学年、職務など)、どんな場面で読むか、自分で扱える形、人物像(ロールモデル)が書かれている |
| 読後に期待すること | 「読者が〜できる」「読者が〜と分かる」「読者が〜を〜とも見られる」の形の一文。構成を含まない(R2.5) |
| 立場 | 文書がとる立場が、外から指定されたか依頼者が決めたかとともに書かれている。なければ「なし」 |
| 切り口 | 依頼者が選んだ着眼点と、主張の一文 |
| 扱う内容 | 必ず扱うもの、必ず使う語、扱わないもの、変えてはいけないもの |
| 制約 | 分量の上限、文体、書式、提出先や出題の規定、媒体(common.md N1.24) |
| 資料 | 渡す資料と、author-style の場所 |

- R2.2 読者、読後に期待すること、切り口は必須とする。承認を求める時点で、この3つの欄の値は「未決」にできない。
- R2.5 読後に期待することに、構成を書かない。「根拠を2つ挙げられる」のように個数や並びを書くと、書く担当はそれをそのまま節の並びにする。依頼者が個数や並びを指定したい場合は、制約に書く。依頼者の言葉が構成を含む場合は、読者に起こすことの形に言い直す案を示し、確かめる。
- R2.6 分量は、上限として決める。依頼者が目安や幅で答えた場合は、幅の上の値を上限とする。下限は、提出先や出題の規定で定められた場合だけ置く。

## R3 author-style

- R3.1 壁打ちの議論に準拠して、author-style-template.md の欄を書く。議論で直接出なかった欄も、議論に沿う定めであれば書いてよい(依頼者の承認で定めになる)。議論から決めようのない欄は「未決」のまま残す。未決の欄は、定めがないものとして扱う(common.md N3.6)。
- R3.2 用語・表記表(第3部)の固定する語は、依頼者が壁打ちで選んだ語だけを書く。AIは自分で語を固定しない(common.md N1.10)。
- R3.3 依頼者が author-style を持ち込んだ場合は、それを使い、議論と食い違う欄だけを追記案として示す(handoff.md N4.2)。

## R4 作って承認を得る

- R4.1 要件定義書は、依頼者の言葉をできる限りそのまま使い、AIの言い換えで意味を広げない。置き場所は records/brief.md(handoff.md N5.4)。
- R4.2 承認を求める前に、次の3つを確かめる。必須の3つの欄(R2.2)が基準を満たしている。依頼者が承認していない案が入っていない。読後に期待することに構成が書かれていない。
- R4.3 要件定義書と author-style を示して承認を求める(承認の形)。承認を得たら、論点案の作成へ進む。
