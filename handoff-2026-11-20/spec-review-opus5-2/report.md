# doc-specs 点検報告(経緯を知らない立場から。対象は main、e45c1f7)

点検の担当(opus。effort は既定。経緯の記録は渡していない)の報告。担当が返した本文を、窓口がそのまま保存した(2026-11-20)。担当はファイルの書き換えと git の操作をしていない。根拠は指定された範囲の文面だけである。review/base-v4.md は前置きしか読んでいないので、写しの中身に関わる点は「前置きの文面からは判別できない」と書いてある。

## 影響の大きい問題(上位3つ)

1. ふつうの会話(基準の環境)では、受け渡しの定めどうしが一往復の中で両立しない。台帳を毎回まるごと返すのか、まったく返さないのかが決まらず、「作業中(返事は要らない)」の発言では流れが止まる(N5.4・N7.5・Z4.1・N6.5)。
2. 依頼者が「任せる」と言ったときに承認の関門をどう扱うかが、段ごとに違う。そのため (2)「全部任せる」の流れが一通りに読めない(Z4.2・YN の前文・W2.1・Z5.4・O4.3・W1.2・N6.1)。
3. 検証担当の作業種別「書く側の要求つき」に穴が三つある。読む範囲の U2 が、読んでいないファイルの語を使い、U1.4 と逆の指示をしている。結果の値が3か所で食い違っている。依頼者が書いた本文では、確かめる事項を拾う者がいない。

## 見つけた問題(影響の大きい順)

**1 / 構造 / handoff.md N5.4・N5.5、common.md N7.5、phase-1 Z4.1**
- 問題:ファイルを書けない環境の定めが三つあり、互いにぶつかる。台帳には話が進むたびに行を足す。変えたファイルは丸ごと返す。ところが、会話には承認の形だけを出す。窓口は、壁打ちの一発言ごとに台帳の全文を貼るか、まったく出さないかのどちらかになる。出さなければ、次の会話に台帳が渡らない。さらに「今の状態」は「会話の終わり」に書き直す定めだが、ふつうの会話では、AIには会話の終わりが分からない。
- 根拠:Z4.1「話が進むたびに、台帳に行として書く」。N5.4「変えたファイルを丸ごと…返し」。N7.5「成果物の全文はファイルに置き、会話にはこの形だけを出す」。N5.5「区切り(段の終わり、会話の終わり)ごとに窓口が書き直す」。
- 直し方:N5.4 の箇条に一行足す。「ファイルを書けない環境では、台帳と変えたファイルは、承認の形を出すときと依頼者が中断を告げたときに、まとめて返す(N7.5 の『この形だけ』はファイルを書ける環境の定めとする)」。

**2 / 暗黙の了解 / common.md N6.5**

- 根拠:N6.5「『作業中』(返事は要らない)」。
- 直し方:N6.5 に一行足す。「ふつうの会話では作業中を使わず、なりきりの続きは同じ返答の中で行い、返答は確認待ちか議論中で終える」。
