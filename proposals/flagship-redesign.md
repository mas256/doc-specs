## 1 出発点:冗長さの診断

依頼者の所感:規格は、何を書くか・どう直すかに重点があり、削る・捨てる指示が弱い。そのため冗長になりやすい。読者への寄り添い方を間違え、細かすぎる段差で議論が進む。

診断(依頼者と合意済み):

- 根本は、読者の像が前提知識だけで決まっていること(N1.1)。読者がどれだけの段差を自分で越えられるかの欄がなく、補完が要る箇所はすべて飛躍(N1.5)の候補になる。越えられる段差は、位置(後ろの章・付録ほど大きい)と再登場(一度示した変形)で変わる。
- 負担の原因の7符号(N2)は、どれも「欠け」の種類で、改善の方向が足す向きしかない。レビューが符号を付け(C6.2)、改稿がその方向で直す(E3.2)ので、流れ全体が足す方向に回る。
- 削る規定はあるが、立証の負担が逆向き。C3.2・C5.6・C3.7・C4.7 の歯止め(短さだけで削らない等)は、短さ偏重の失敗への手当てとして意図して入れたものなので、単に外さない。
- 方針は「最小の変更」(core の方針の規定)で、組み直し(N2.1)は条件が狭い。指摘が箇所ごとの欠陥から始まるので、変更は部分修正にとどまり、大きな組み直しが出ない。
- 講義型の既定値(Y3 の「未知を極限まで減らす」「難解な演繹は細かく分割する」「言い換えを多用する」)が、刻みすぎと冗長さを生む。
- 実例:Integral 1.5 で、書き直しのときに Σ の説明の1文が足された。Σ は 1.2 で導入済みで、承認済みの草案は「2回目以降は説明しない」と定めていた。

## 2 規則の種類と、判断力への作用

過剰な指示は、AIの判断力を鈍らせ、品質を下げうる。規則を、判断への作用で4種類に分ける。

| 種類 | 例 | 扱い |
| --- | --- | --- |
| ① 判断の代わりをする | M2.2 の組み立ての段、M3.1〜M3.7 の「〜を飛ばさない」、講義型の既定値 | 大きく削る候補。小さいモデル向けの手順としてだけ残す |
| ② 判断の材料を渡す | 想定読者、到達点、越えられる段差、読み方、見本、判断の記録 | 残し、充実させる |
| ③ 偏りを打ち消す | 書き手と評価者を分ける、論点を足さない、自己評価しない、未確認を明示する | 残す。最小限にする |
| ④ 手続き・受け渡し | ID、台帳、書式 | スクリプトに移し、AIの読む量から外す |

- 負担の原因の分類(N2)は、評価者の物差しとして残し、書き手への禁止としては渡さない。

## 3 モデルの格と、制御の手段(決定)

- フラグシップ(Fable など):創造性を依頼者の創造性に合わせる。効くのは規則ではなく、依頼者の判断とその理由。
- ミドルレンジ:案を書く。指示に忠実で、ある程度の文章力がある。
- 軽量モデル:具体的な指示を忠実に実行する。判断の材料を漏れなく集める。何も知らない読者の代わりにもなる。

フラグシップに渡すもの:

1. 判断の記録:採った版と捨てた版の組と、選んだ理由。決定だけでなく理由を渡す(初めて見る箇所にも同じ考え方を当てられるようにするため)。
2. 価値の優先順位(例:厳密さより分かりやすさ)。
3. 依頼者が退けた案と、その理由。

- author-style の「判断の入る方針」を、規則の箇条書きから判断の記録へ作り替える方向。
- 合わせ具合は測れる:依頼者にまだ見せていない較正の素材で、フラグシップに依頼者の選択を予想させ、一致した割合を見る。外れた件の理由を判断の記録に足す。
- 依頼者の傾向から外れた案は、あまり出さない。より良いものを作るために複数案を作らせ、それを元に選び・組み合わせる形を最善とする。

## 4 工程の流れ(決定。2026-11-14 に10工程から5工程へ改めた)

工程は、成果物が受け渡される区切りで数える。割り振りと選択は、フラグシップの中で済む行為なので、独立した工程にせず、工程の中の手順として扱う(Flower & Hayes のモデルで、過程を切り替える「監視」を独立の過程にしないのと同じ。research-2026-11-14.md の A2・B1)。

| 工程 | 担当 | 内容 | 依頼者の承認 |
| --- | --- | --- | --- |
| 1 要件定義 | フラグシップ | 方針、性質、読者の像、判断の記録(較正) | あり |
| 2 草案 | フラグシップ | 章立てと、単位ごとに伝える内容(草案の項目) | あり |
| 3 骨組み | フラグシップ+ミドルレンジ | フラグシップが作業パケット(草案の項目、入口と出口、変える軸)を書く。ミドルレンジが、指定された軸に沿って骨組みの案(構え・順序・使う例・段差の方針を数行ずつ)を複数、1回の作業パケットでまとめて出す。フラグシップが1〜2案を選ぶ(組み合わせてもよい) | なし |
| 4 本文 | フラグシップ+ミドルレンジ+軽量 | ミドルレンジが、選ばれた骨組みを本文の案にする(草案の項目と本文の位置の対応表を付ける。前の単位の終わり方を受け取る)。フラグシップが選んで組み合わせ、選んだ理由を判断の記録に足す。最後に軽量モデルが、つなぎ目の用語・表記・参照を照合する | なし |
| 5 検証と改稿 | 別の文脈のフラグシップ+軽量 | 独立したレビュー(現行のレビュー規格が担う。書いた・選んだ会話の内容を引き継がない)と、軽量モデルによる改稿(フラグシップが書いた具体的な指示どおりに直す)を、基準を満たすまで繰り返す(生成と評価の繰り返し。基準は要件定義と ISO の4原則で明確にする) | 採否は依頼者が決める |

- 長さの偏りへの対策(2026-11-14 決定):工程3・4の作業パケットには、比べる案の分量をそろえるか明示すること、長さを選ぶ理由にしないことを必ず書く(research-2026-11-14.md の A3)。
- 創造性が入る場所は、工程2の草案の項目(何を書くか)と、工程3・4の選択(どれが良いか)。書く担当には創造性を求めず、幅(複数案)を求める。
- 工程2で承認された草案の項目が、工程3以降の正本である。
- 箇条書きの深さ:最下層を、ミドルレンジに1回の作業パケットで渡す単位にそろえる。基本は章まで。漸化式・積分の教科書の規模では、節や小節まで下ろす。深さは要件定義で、分量と媒体から決める。
- 割り振りの単位が承認された階層より細かくなる場合、フラグシップが決めてよいのは草案の項目の配分と順序だけで、新しい草案の項目は足さない。足す必要が出たら、草案に戻して承認を得る(W2.3 と同じ扱い)。
- つなぎ目:単位の中(組み合わせた案どうし)と、単位の間(前の終わり方と次の始まり方)の両方。単位は前から順に書くので、並行できる範囲は狭まる。
- 書き手と評価者を分ける(C1.3)ことは、工程5で、別の文脈のフラグシップに行わせる形で保つ(同じモデルでは自己選好を防げない点は §10 の14)。

## 5 案ごとに変える軸

表の両端の例は一般の文書の言葉で書き、数学書での例は( )に添える。

単位ごとに、フラグシップが迷う軸(判断の記録に前例がない軸)を2つほど選ぶ。両端を取れば、案は最大4つ。前例のある軸は記録どおりに固定する。

| 分類 | 軸 | 両端の例 |
| --- | --- | --- |
| 入り方 | 構え | 問いから/結論から/例から/困りごとから |
| | 動機づけ | 実地の観察・試行から(数学書:実験)/経緯から/用途から/前置きなしで本題へ |
| 順序 | 一般と特殊 | 一般論→例/例→一般論 |
| | 論証の向き | 前提から結論へ/結論から必要なものへさかのぼる |
| 段差 | 段差の大きさ | 中間の段階を全部示す/操作や判断の名前と結果だけ(数学書:中間の式の有無) |
| | 分量 | 丁寧版/簡素版/限界まで削った版 |
| 例 | 数と働き | 例1つを深く/新しい注意点を持つ例を複数 |
| | 種類 | 具体的な数値や事例/図/反例・失敗例/実際の利用場面 |
| | 位置 | 一般論の前/後/途中に挟む |
| 表現手段 | 比重 | 文章中心/記号・式・コード中心/図や表中心 |
| | 図の位置 | 図を先に見せる/文章の後で確かめる |
| 層 | 振り分け | 理由・例外を本文に置く/注釈に回す |
| | 厳密さ | 条件を本文で述べる/本筋は条件なしで進め、注釈で補う |
| まとめ | 回収 | 要約の枠で要約する(数学書:POINT)/次の単位への問いで終える/まとめなし |

- 変えない軸:文体(語尾、呼びかけの調子)と用語・表記。author-style で決まっている。
- 内容の軸(説明の筋そのもの)は、この表の軸と違ってミドルレンジに任せない。§9a のとおり、フラグシップが工程2で扱う。

## 6 展開の型と構え

- 展開の型が分かりやすさを生む仕組みは2つ。構え(冒頭で主張・問い・行き先を渡すと、読者はそれを成立させようとして読む)と、予測(各段の役割の並びが読める)。起承転結は流れそのものを明瞭にとらえる。
- 一般化した原則:単位の冒頭で構えを渡す。各段がその構えに対して何をしているかを読者が言える状態を保つ。最後に回収する。
- 展開の型は、守らせる規則ではなく、骨組みの案の候補として使う。破るときは行き先を告げる(黙って破ることだけを禁じる)。単調さは、隣り合う単位で同じ型が続くことで起きるので、型の並びも見る。
- 一般の文書への一般化は、分野ではなく性質(読者がその文書で何をするか)で分ける。性質の分け方は §0 と §10 の未決事項を参照(外部の指摘 F8)。型ごとに、構えの渡し方・越えられる段差・検証の対象の既定値を持たせる。
- 現行の O3.8・M3.10・core の方針の規定が退けているのは、展開の型を一律に課すこと。単位ごとに候補として出し、選ぶ使い方とは衝突しない。文言の調整で足りる見込み。

## 6a 性質の3つの層(2026-11-14 決定)

読者がすること(報告・提案・説明・物語・指示・論証・参照・演習・規範・記録)で一つに分ける案は、違う層を混ぜていて重複が多かったため、退けた。言語学でも、何のために伝えるか(Searle の発話行為の分類、Kinneavy の談話の目的)と、どう運ぶか(Werlich の文章の型)は別の層として扱われる(research-2026-11-14.md の B4)。

- 層1 伝えたいこと(目的):

| 伝えたいこと | 読者に起こしたいこと | 冒頭で渡す構え | 検証の重点 |
| --- | --- | --- | --- |
| 事実を伝える | 知る | 結論(何が、どうなっているか) | 正確さ |
| 要望を伝える | 動く(依頼、指示) | 求める行動 | 実行できるか |
| 理由を伝える | 納得する(主張、提案の根拠) | 主張 | 根拠と反論への応答 |
| 気持ち・体験を伝える | 感じる(物語、表出) | 状況と引き | 一貫性 |
| 決まりを伝える | 従う(規程、決定) | 適用範囲 | 定義が一通りに決まるか、矛盾がないか |

- 層2 運び方:描写/叙述(時系列)/説明(分解)/論証/手順(Werlich)。展開の型の候補はこの層が持つ。
- 層3 読み方:通読/拾い読み/参照。段差の既定値と、各部分が単独で読めるかはこの層が持つ。
- 文書全体に既定の性質を付け、章・節ごとに付け直せる。性質どうしが衝突したときの優先順位は要件定義で決める。
- 旧案の組み合わせでの表し方の例:報告 = 事実 × 叙述 × 拾い読み/提案 = 要望+理由 × 論証/指示 = 要望 × 手順/参照 = 読み方の層だけ/演習 = 要望(練習させる)× 手順。
- チューニングの枠(§7)は、各層が自分の列だけを持つ形にする。

## 6b 既存の理論の語彙を使う(2026-11-14 決定)

独自に作った語彙は、できるだけ既存の理論の語彙に置き換える(research-2026-11-14.md の B3・B5)。

- 修辞構造理論(RST)の核と衛星:削除の試験(衛星は文章の主な働きを壊さずに取り除けるが、核は取り除けない)を、「削る・注釈に回す」の判定に使う。§9b の「展開の中の働き」は、RST の関係の一部で置き換える方向(具体的な語の選定は未決。§10 の12)。
- ISO 24495-1 の4原則(必要なものを得られる/見つけられる/理解できる/使える):文書ごとの成功の基準(§10 の9)の最上位の枠として使う。今の J1〜J5 や、性質ごとの検証の重点をこの下に整理する(整理は未決)。

## 7 要件定義の厳密化

- 言葉ではなく見本で決める(較正):AIが素材の短い一節を、段差・構え・層の違う2〜3の版で書き、依頼者が選ぶ。選ばれた版と選ばれなかった版の組と理由を、判断の記録として残す。漸化式の議論で決め手になったのは、現在の版と圧縮した版を並べて選んだ場面だった。
- 決める項目:性質、越えられる段差、構えの渡し方、展開の型を守る強さ、意図した繰り返しと読み方、層、厳密さ、分量と測り方。
- 項目は見本を主にし、言葉は見本の補足にとどめる(規則を書かせる方向に寄せない)。
- 性質を選べば既定値が入り、依頼者に尋ねるのは既定値から外れる項目だけにする。較正は長い文書で、段差と構えに絞る。
- 後から直す道を設ける:レビューの不採用の理由や依頼者の反応から、判断の記録を改める(外部の提案 P11)。その値が較正で決まったか、後から直したかを記録する。
- 両立しない定めを残さない規定(R3.4)を、文体の型の一覧(style-presets)と性質の既定値を、選んだ値との突き合わせにも広げる。

## 8 サブエージェントへの指示の書き方(フラグシップ向け指示書に入れる)

担当の知識は、固定の定義から、フラグシップがその都度書く作業パケットへ移す。固定の定義は「指示に従う。指示にないことはしない。判断が要るときは止めて返す」程度に薄くする。

1. 判断を残さない:読者の像や好みが要る判断は、フラグシップが先に済ませる。
2. 入力を閉じる:読むファイルと行の範囲を指定する。
3. 出力の形を固定する:フラグシップが機械的に照合できる形にする。
4. 確かめ方を付ける:完了の条件を書く。
5. 止まる条件を書く。
6. 一つの指示に一種類の操作。
7. 見本を付ける:入力と出力の組を1つ。
8. 禁止は具体的に書く(「冗長にしない」ではなく「方針にない文を足さない」)。

- 「集めるのは軽量、決めるのはフラグシップ」:過剰の候補の一覧、伝えたい内容の初出の行、表記・参照の照合などは軽量モデルが漏れなく集め、採否はフラグシップが決める。
- ミドルレンジへの指示(骨組みの案・本文の案)は、上の8項目に加えて、草案の項目・入口と出口・変える軸・変えない軸を必ず含める。

## 9 これまでに出た個別の案(位置づけは未決)

- 負担の原因に「過剰」を加える(段差・到達・一般化・層・定型・結び付かない繰り返し)。外部の指摘 F3(N2 を「支障の原因」に改め、J3 の指摘にも符号を必須にする)と一度に行う。評価者の物差しとして持ち、書き手への禁止にはしない。
- 到達の遠さを節の単位で測る:伝えたい内容が節の何行目に初めて現れるか。
- 本文・注釈の層を書く工程の規則にする(理由・例外・厳密さ・参照の案内は注釈へ)。
- 意図した繰り返しは、要件定義で挙げた読み方に結び付くときだけ正当とする。
- 方針を起案するとき、足す文が新たに生む負担を、解消する負担と比べる。負担が低の指摘は、文を足して解決しない。
- 再構成担当:欠陥ではなく単位の目的を起点に、部品(残す・削る・まとめる・並べ替える・注釈へ)を組み直す案を、試作の文つきで出す。新しい流れでは、工程4〜7(骨組みの案と選択)がこの役目をほぼ吸収する。既存の本文の改稿でどう使うかは未決。

## 9a 内容の代替:より良い説明の筋を探す(決定)

きっかけ:漸化式の教科書で、依頼者が、定数の付加項がある隣接3項間型について、より良い解法に気づいた(付加項 r を消さずに付けたまま変形し、特性方程式型と同じ形の2項間の式を2本立てる)。現行の解法は正しく、読者も追えるので、どの担当も問題にしなかった。

診断:今の規格は、内容を与えられたものとして扱い、伝え方を磨く作りになっている。M1.2(草案にない論点を足さない)、W1.1(内容の採否はAIが決めない)、C3.7(詳しさは書き手の裁量)、方針の「最小の変更」、E4.4(採否表にない論点を足さない)は、AIが勝手に論点を足す失敗を防ぐ一方で、より良い説明の筋を提案する場所まで消している。指摘は欠陥から始まるので、欠陥のない説明は見直されない。再構成担当も、既存の部品の並べ替えにとどまる。

用語:説明の筋 = 読者を出発点から到達点(変化)まで運ぶ手段の組み立て(枠組み、比喩、手順、論拠の並べ方など)。数学書では「解法」に当たる。

### 草案の工程(工程2)

- 要所の単位について、同じ到達点に至る別の説明の筋を、フラグシップが探す。「AI提案」として草案の項目の案と並べて示し、依頼者が採否を決める。

### レビューの段

- 「改善できるか」を厳密に判定することは、新しい説明を考えることとほぼ同じで、すべての内容に行うとコストが見合わない。そこで、改善の余地が「ありそうな」箇所だけを、外から分かる兆候で絞る。
- 兆候(一般の形。数学書の例は( ))
  1. 例外や但し書きが積み上がっている(「定数でずれを戻せないとき」の段/規程の「ただし〜の場合は」の連続)
  2. 並列する単位どうしで、枠組みがそろっていない(付加項の有無で解き方が違う/起案書で案Aは費用、案Bはリスクで評価している)
  3. 一度しか使わない道具を導入している(隣接3項型のためだけの平行移動/その章でしか使わない比喩や独自の分類)
  4. 後の単位で、同じ問いに別の枠組みで答え直している
  5. 動機のない一手がある(「結論から示す」で始まる変形/起案書で、なぜ今決めるのかがない)
  6. 分量が、伝える内容に比べて大きい
- 兆候は判断なしに集められるので、軽量モデルに漏れなく拾わせる。
- 流れ
  1. 軽量モデルが兆候を集める。
  2. フラグシップが、兆候の重なる単位から順に選ぶ。**上限は1回のレビューにつき3件**(2026-11-14 決定。採用率を見て調整する)。
  3. 選んだ単位について、既知の代替を挙げ、骨組みだけを示す(本文は書かない)。
  4. 提案(P)として返す。採用されたら草案の項目の変更なので、工程2に戻して依頼者の承認を得る。
- 既知の代替を挙げる(知識を引き出す。安い)と、新しい説明を作る(高い)を分ける。レビューの中では前者だけを行う。既知の代替は、読者の仕事の型ごとに持つ(判断:比較表、判断基準ごとの評価、結論→根拠/手引き:一本道の手順、分岐の図、目的別の索引/伝達:結論先行、時系列、変更点だけ/解説:問い→試み→解決、例→一般化、既習の操作の再利用)。外部の指摘 F8 とつながる。
- 「より良い」の基準:再利用(既に読者に渡した枠組みで済むか)、例外の少なさ、適用範囲(同じ筋でより多くの場合を扱えるか)、読者の手間。基準どうしはぶつかりうる(例:定数の付加項で特性方程式の解に1がない場合は、平行移動の方が速い)ので、重み付けは本ごとに判断の記録(較正)で決める。

### 依頼者の気づきの入口

- 兆候の出ない改善は見逃す。それは受け入れる。代わりに、依頼者が「ここはもっと良くできる」と気づいたとき、フラグシップがそれを骨組みの案にし、あわせて兆候の表への追加項目にする。気づきが兆候の表を育てる。
- 兆候の表は1例から作ったもので、他の単位で当てはまるかは未確認。

## 9b 判断の記録(決定)

フラグシップが工程3(骨組みの選択)と工程4(本文の選択と組み合わせ)で選ぶときの拠り所。§3 の「判断の記録」の具体化。

### 記録の項目

| 項目 | 中身 |
| --- | --- |
| 論点 | どの軸の判断か。閉じた一覧(§5 の軸と、内容の軸)から選ぶ |
| 条件(場面) | 理由が依存している特徴だけを、下の語彙から選んで書く |
| 選んだもの、捨てたもの | 両方を短く書く |
| 理由 | その場の事情ではなく、ほかの場面にも当てられる形で書く |
| 適用範囲 | この本だけ/この性質/依頼者の文書全般 |
| 出どころ | 較正/依頼者の再作成/レビューでの不採用/依頼者の気づき/フラグシップの仮決め |
| 依存する単位 | 仮決めの場合、その仮決めの上に作った単位 |

### 抽象化:理由が依存する特徴だけを残す

- 細かすぎると前例が当たらず、粗すぎると誤って当たる。抽象化の水準は理由で決める。理由が成り立つのに必要な特徴だけを条件に残し、関わらない特徴は捨てる。
- 条件の特徴は、自由に書かず、決まった語彙から選ぶ(照合できるようにするため)。出発点の語彙:
  1. 粒度:判断が関わった単位の大きさ(章、節、数文、表現)。単位は N1.3 の単位(文書を構成する、読者に一つの変化を起こすまとまり)で、文書全体ではない。比べる案の大きさ(割り振りの単位)と、判断が関わる大きさが違うことがあるので、後者を書く。
  2. 展開の中の働き:構えを渡す/支える/具体化する/転換する/回収する。展開の型の段の名前ではなく働きで書く(下の対応表)。展開の型が違う文書どうしでも記録が当てはまるようにするため。
  3. 文書の中の位置:前半/後半/付録・発展。読者がそこまでに積み上げたもの(既習の量、慣れ、意欲)を表し、型には左右されない。
  4. 初出か再出か(何回目か)
  5. 読者の意欲
  6. 誤解のおそれ(身近な反例があるか)
  7. 本筋からの距離
- 性質ごとの特徴は後から足す(例:提案の性質なら、読み手の権限、決定の重さ)。新しい理由が語彙にない特徴に依存するときだけ、語彙を1つ増やす。

| 働き | OREO | 起承転結 | 問い→試み→解決 |
| --- | --- | --- | --- |
| 構えを渡す | 主張(O) | 起 | 問い |
| 構えを支える | 理由(R) | 承 | 素朴な試み |
| 具体化する | 例(E) | 承 | 試みの中の例 |
| 転換する | — | 転 | 行き詰まり |
| 回収する | 主張の再提示(O) | 結 | 解決 |

記録の例(漸化式の議論から):

| | 問11の帰納法 | 添字のずらし |
| --- | --- | --- |
| 論点 | 段差(段差の大きさ) | 厳密さ・層 |
| 選んだもの | 式だけを見せる | 「この数列は」と範囲を限り、理由は注釈へ |
| 捨てたもの | 変形の各段の説明 | 「$k\le0$ で $a_k$ は未定義」という一般論 |
| 理由 | 本筋から外れた発展の話題まで読み進める読者は、難しさに耐える | 一般論で述べると、反例を知る読者に誤解を生む |
| 条件 | 位置:付録・発展/本筋からの距離:遠い/読者の意欲:高 | 誤解のおそれ:身近な反例がある($a_0$ から始まる数列) |

### 照合

- 論点が一致し、記録の条件をすべて満たせば前例とする。
- 一部だけ満たす場合は「類推」とし、仮決めと同じに扱う。
- どちらの場合も、フラグシップは、どの記録を当て、なぜ当てはまるかを1行で書く(依頼者が後から確かめられるようにするため)。

### 前例がないとき

| 判断の重さ | 当たる判断 | 扱い |
| --- | --- | --- |
| 大 | 草案の項目や構成に関わる | 必ず尋ねる(工程2の承認がこれに当たる) |
| 中 | 骨組みの選択で、迷う軸に前例がない | フラグシップが仮に決めて記録する |
| 小 | 表現の範囲 | フラグシップが決める。報告しない |

- 確認の時機は件数で決めない。危険は、仮決めの上に積み上がる量で決まるため。
  - 仮決めは1回限りとし、その単位にだけ使う。
  - 同じ判断がもう一度必要になり、仮決めを前例として使おうとした時点で、依頼者に確かめる。確かめるまでは前例にしない。
  - 一度しか出なかった仮決めは、章の区切りでまとめて示す。
  - 示すときは、採った案と捨てた案を並べる(較正と同じ形)。条件もあわせて確かめる。
  - 依頼者が覆したら、依存する単位だけを作り直す。
- 抽象化の水準を直す道:記録を当てた判断を依頼者が覆したら、条件が粗すぎた(特徴を1つ足して狭める)。仮決めに「前と同じでよかった」と言われたら、条件が細かすぎた(特徴を1つ外して広げる)。

### 記録どうしの関係

- 適用範囲の狭い記録を優先する。
- 同じ範囲どうしで食い違ったら、新しい方を自動で優先せず、依頼者に理由を書き直してもらう事項として挙げる(2026-11-14 決定)。
- 漸化式で作った記録は、Integral でも使ってよい。共有するのは適用範囲が「依頼者の文書全般」の記録だけで、「この本だけ」の記録は参考にとどめる(2026-11-14 決定)。

### 初期の乗り切り方

- 要件定義の較正を、前例のない判断が最も多く出そうな軸(段差、構え)に絞る。
- まだ見せていない較正の素材で、フラグシップに依頼者の選択を予想させ、一致率を見る。
