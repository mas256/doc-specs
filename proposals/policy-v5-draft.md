# 文書作成の方針(草案4。向きは依頼者が承認、2026-11-17「a」)

根拠:proposals/flagship-redesign.md(11/14 の核)、trials/essay-2026-11/analysis-1.md(11/15 の総括)、handoff-2026-11-16/flow-decisions.md(依頼者の書き方の流れ)、第4版の試行(trials/2026-11-17-v4/result.md)。

0. 文書の作り手は依頼者である。AIは、議論の相手、調べ物、案出し、下書き、読み手としての指摘で、依頼者の作成を手伝う(依頼者が採用、2026-11-18)。AIだけで書き切る使い方は、依頼者が「任せる」と決めたときの一つの使い方として残し、流れの中心には置かない(1a)。AIだけの試行は、ベンチマークとして行うもの。
1. 厳密と自由を、場所で分ける。
   依頼者が決めたこと(読者、読後に期待すること、立場、制約)は厳密に守る。
   依頼者が決めていないこと(着眼、題材、例、脇道、構成の組み方、日本語の書き方)は、AIが自由に広げる。
2. 広げて、選ぶ。
   自由な場所では、AIはたくさん出し(調べ、視点を増やし、何パターンか作る)、依頼者が選ぶ。
   選んだもの・捨てたものと理由を残し、次に選ぶときの選ぶ基準にする。これが、テンプレートの部品として育つ。
3. 依頼者の書き方をなぞる。
   決める → 出す → 選ぶ → 並べる → 書く → 読んで直す。直すときは、問題の性質に応じた場所に戻る。
4. 単純に始め、失敗が見えたときだけ足す。

- 選ぶときの選ぶ基準:読者を芯にする(読者から見て判断する)。論理の面(筋が通り、現実的か)と、表現の面(わかりやすく面白い日本語か、書き手の意図を保っているか)を分ける。
- 調べ物:事実の確かめと、題材・切り口・視点を増やすために使う。答えを得るために調べない(依頼者の決定)。


## 段ごとの受け持ち(2026-11-18)

| 段 | 依頼者 | AI |
| --- | --- | --- |
| 壁打ち | 議論する。何を書くかを決める | 議論の相手。広く調べる。切り口の案を出す |
| 論点案の作成 | 選ぶ | 選んだ切り口を補強する案を出す。事実を確かめる |
| 構成案の作成 | 並べ方を決める | 並べ方の案を何パターンか出す |
| 執筆 | 書く。または、AIの下書きに手を入れる | 依頼者が求めた部分を下書きする。依頼者の文を読んで指摘する |
| 読んで直す | 直すかどうかを決め、直す | 読者として読み、弱いところと理由を示す。誤植を直す |

## 流れ(依頼者が承認、2026-11-18「承認、1a」)

```text
壁打ち(議論・広い調べ物・切り口の複数案。要件定義と author-style を決める)
  ⇄ 論点案の作成(選んだ切り口を補強する)
  → 構成案の作成 → 執筆 → レビュー・改稿
```

### 1 壁打ち

1. 最初に伝える:これから壁打ちを行い、その結果から author-style と要件定義を作ること、依頼者が終えると言うまで続けること。
2. 言い直して尋ねる:AIが依頼を理解するための段。要件定義書を埋める段ではない。
3. 広く調べて、切り口の案を出す:題に関わる話題・事実・見方を、とても広く、深くしないで調べる。切り口の案(着眼点、主張の一文、主な題材)を複数出す。
4. 議論する(依頼者が「終える」と言うまで):切り口の案を材料に話す。依頼者の見方も切り口の一つとして並べる。混ぜる・足す・捨てるを繰り返し、依頼者が向きを決める。必要ならその場で調べ直す。ねらいは、目的を定めることと、依頼者がその事柄への理解を深め、監督の質を上げること。
5. 作る:終える指示の後、壁打ちメモから author-style と要件定義書を作り、承認を得る。選んだ切り口(向きと主張)は、要件定義書の欄に書く(1a)。

### 2 論点案の作成

1. 材料:要件定義書(選んだ切り口を含む)、author-style、壁打ちメモ。
2. 補強の調べ物:選んだ切り口の題材の裏付け、具体例、一段深い調べ。新しい切り口は探さない。
3. 確かめる:検証担当が使う題材の事実を確かめ直す。ロールモデルの担当が、現実的か、身近か、新しいかを読む。
4. 示して選ぶ:論点の案(核を支える題材の組み合わせ、余談に別の場所に置く候補)を示し、依頼者が承認する。

### 3 構成案の作成へ渡すもの

選んだ切り口、論点の案、別の場所に置く候補。構成案は、何を言うかと並べ方までを決める(文面と字数は書かない)。

## 要件定義書(依頼者が承認、2026-11-18「2a」)

```text
# 要件定義書:[文書名](版・日付)
読者: (誰か。どんな場面で読むか。自分で扱える形。人物像)
読後に期待すること: (一文)
立場: (あれば。なければ「なし」)
切り口:
  着眼点: (どこに目を付けるか)
  主張: (一文)
扱う内容: (必ず扱うもの、必ず使う語、扱わないもの、変えてはいけないもの)
制約: (分量の上限、文体、書式、提出先や出題の規定、媒体)
資料: (渡す資料、author-style の場所)
```

- 読者、読後に期待すること、切り口は、「未決」のまま承認しない。

## author-style(依頼者が承認、2026-11-18「3a」)

壁打ちの議論に準拠して、テンプレートの欄を書く。議論で直接出なかった欄も、議論に沿う定めであれば書いてよい(依頼者の承認で定めになる)。議論から決めようのない欄は未決のまま残し、定めがないものとして扱う(書く担当の自由)。用語の固定は、依頼者が求めたときだけ書く。
- 依頼者(2026-11-18):「議論で出たことだけ、といいましたが、限定にすると自由度が狭まりAIの回答の質が下がりそうなので準拠する、に改めてください」。

## 語(依頼者が承認、2026-11-18「1a」)

向き → 着眼点、主張の核 → 主張、草案(工程の名前)→ 構成案の作成、移す候補 → 別の場所に置く候補、現実と地続き → 現実的か、物差し → 選ぶ基準、論理の軸・表現の軸 → 論理の面・表現の面。指示役という名前はなくし、窓口に一本化する。

## 構成案の作成(依頼者が承認、2026-11-18「1a」)

1. AIが並べ方の案を出す:論点案(選んだ切り口と題材)から、並べ方を2〜3パターン出す。小さい文書(小論文など)では1パターンでよい。一つのパターンは、段落ごとに「その段落で何を言うか」を一行で書く。依頼者「切り口ベースなので以前よりたくさんの案を出す意味は減りましたが、案を出すことにします」。
2. 依頼者が決める:並べ方を選ぶ。混ぜる・入れ替えるのは自由。依頼者が決めたこと(この段落はこの例から入る、ここは強調する、など)は、その段落の欄に書く。
3. 決めていない欄は「任せる」:欄はすべて載せるが、依頼者が決めていない欄の値は「任せる」にする。AIの見立てで中身を埋めない。
4. 書かないもの:本文の文面、段落ごとの字数、言い回しの固定。字数は全体の上限(要件定義書の制約)だけ。

## 執筆(2026-11-18)

- 書き方は、文書ごとに依頼者が決める。AIが下書きして依頼者が手を入れるか、依頼者が書いてAIが読者として読んで指摘するか(段落ごとに分けてもよい)。任せきりのときは、AIの下書きのまま次へ進む。依頼者「a,b両方でいけるようにしましょう。1件分岐が増えて指示が増えそうに見えますが、1行で済むはずです」。
- よい日本語の基準(AIが下書きするときに目指し、読んで指摘するときに見る):
  1. 1文1主張(1内容)。二つをつなぐのは、逆接(〜だが)や順接(〜であり)を状況を鑑みて使うときだけ。
  2. 最初の文で引く。書き手が勝手に思っただけ、と読める入り方にしない(読者が共感できる入り方)。
  3. 問い掛けは、オープンクエスチョンにする。
  4. 中心になる語(パンチのあるワード)は、最初のほうに出して気を引く。
  5. 指示語(その数、それ、この〜)は、何を指すかが読者に分かるときだけ使う。
