# 文書作成の方針(草案4。向きは依頼者が承認、2026-11-17「a」)

根拠:proposals/flagship-redesign.md(11/14 の核)、trials/essay-2026-11/analysis-1.md(11/15 の総括)、handoff-2026-11-16/flow-decisions.md(依頼者の書き方の流れ)、第4版の試行(trials/2026-11-17-v4/result.md)。

1. 厳密と自由を、場所で分ける。
   依頼者が決めたこと(読者、読後に期待すること、立場、制約)は厳密に守る。
   依頼者が決めていないこと(着眼、題材、例、脇道、構成の組み方、日本語の書き方)は、AIが自由に広げる。
2. 広げて、選ぶ。
   自由な場所では、AIはたくさん出し(調べ、視点を増やし、何パターンか作る)、依頼者が選ぶ。
   選んだもの・捨てたものと理由を残し、次に選ぶときの物差しにする。これが、テンプレートの部品として育つ。
3. 依頼者の書き方をなぞる。
   決める → 出す → 選ぶ → 並べる → 書く → 読んで直す。直すときは、問題の性質に応じた場所に戻る。
4. 単純に始め、失敗が見えたときだけ足す。

- 選ぶときの物差し:読者を芯にする(読者から見て判断する)。論理の軸(筋が通り、現実と地続きか)と、表現の軸(わかりやすく面白い日本語か、書き手の意図を保っているか)を分ける。
- 調べ物:事実の確かめと、題材・切り口・視点を増やすために使う。答えを得るために調べない(依頼者の決定)。


## 流れ(依頼者が承認、2026-11-18「承認、1a」)

```text
壁打ち(議論・広い調べ物・切り口の複数案。要件定義と author-style を決める)
  ⇄ 論点案の作成(選んだ切り口を補強する)
  → 草案 → 執筆 → レビュー・改稿
```

### 1 壁打ち

1. 最初に伝える:これから壁打ちを行い、その結果から author-style と要件定義を作ること、依頼者が終えると言うまで続けること。
2. 言い直して尋ねる:AIが依頼を理解するための段。要件定義書を埋める段ではない。
3. 広く調べて、切り口の案を出す:題に関わる話題・事実・見方を、とても広く、深くしないで調べる。切り口の案(向きの一文、主張の核の一文、主な題材)を複数出す。
4. 議論する(依頼者が「終える」と言うまで):切り口の案を材料に話す。依頼者の見方も切り口の一つとして並べる。混ぜる・足す・捨てるを繰り返し、依頼者が向きを決める。必要ならその場で調べ直す。ねらいは、目的を定めることと、依頼者がその事柄への理解を深め、監督の質を上げること。
5. 作る:終える指示の後、壁打ちメモから author-style と要件定義書を作り、承認を得る。選んだ切り口(向きと主張の核)は、要件定義書の欄に書く(1a)。

### 2 論点案の作成

1. 材料:要件定義書(選んだ切り口を含む)、author-style、壁打ちメモ。
2. 補強の調べ物:選んだ切り口の題材の裏付け、具体例、一段深い調べ。新しい切り口は探さない。
3. 確かめる:検証担当が使う題材の事実を確かめ直す。ロールモデルの担当が、現実と地続きか、身近か、新しいかを読む。
4. 示して選ぶ:論点の案(核を支える題材の組み合わせ、余談に移す候補)を示し、依頼者が承認する。

### 3 草案へ渡すもの

選んだ切り口、論点の案、移す候補。構成案は、何を言うかと並べ方までを決める(文面と字数は書かない)。

## 詰めること(順に)

1. 要件定義書の欄と、壁打ちで作る author-style の中身。
2. 草案、執筆、レビュー・改稿。
