# 企画の担当(構成案 Step 2:段落の設計)とのやりとり

- 2026-11-24。同じ担当に続けて話しかけた。

## 作業パケット(窓口 → 担当。送ったものの写し)

```xml
<作業パケット>
  <役割>企画の担当(構成案)。前回と同じ担当として続ける。新たに読むファイルはない(phase-3-outline.md の Step 2 に従う)。</役割>
  <目的>records/03-outline.md を書く。冒頭に「骨格確定記録」(確定した骨格 P-3 の5行と、比較した案 P-4・P-5・P-6 と、依頼者が P-3 を選んだこと)を置き、その下に段落ごとに1行ずつ `[段落番号] 新しく渡す情報/役割 | 使う題材・例 | 詳しさ(厚/中/薄) | 脇道・注意点` で設計する。字数や言い回しは固定しない。返信はファイルの中身と <台帳の行>。git の操作はしない。</目的>
  <入力>
    - 確定した骨格(P-3): (1)A-3 の共通の経験と問い (2)A-1・A-2 の遊びの性質(代表例) (3)B-1〜3・C-1〜3 の三つの変化と考えの動き (4)B-4・D-2 の同時にそろうことと、A-6 の大人に残る遊び (5)C-6 の判定基準、A-4・E-2・E-4 の事例、結論
    - 比較した案: P-4、P-5、P-6
    - 窓口からの注意点: 1. ①が問いを置くだけだと前進のない前振り段落になる。①で何を新しく渡すかを明らかにする。A-3 を「読者も遊んだはずだ」と書くと書き手の思い込みと読める入り方になりかねない。 2. ⑤の役割が重い。結論は依頼者の結論であり、③④の言い換えの繰り返しで終えない。 3. 「覆われる」をどの段落で言い、どこで支えるかを明らかにする。 4. 材料は一般的な知識だけ。数値・固有の大会名は使わない。
    - 要件定義書・論点案は前回読んだもの。
  </入力>
  <文体>author-style.md はまだない。</文体>
</作業パケット>
```
