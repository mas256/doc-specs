# 設計思想（フラグシップモデル・仕様改訂AI・人間向け）

※ 軽量モデルによる通常の執筆会話には渡さない（`START.md` の指示がある場合のみ読む）。

## 5つの基本方針
0. **作り手は依頼者**: AIは材料を広げ、決定は人間が行う。
1. **厳密と自由を場所で分ける**: 仕様（読者・立場・制約・文体）は厳密に守り、発想と日本語は自由に広げる。
2. **広げて選ぶ**: 構成も骨格も文体も、1案で決め打ちせず候補を並べて選ぶ。
3. **依頼者の思考をなぞる**: 決める → 出す → 並べる → 書く → 読んで直す。
4. **単純に始め、失敗が見えたときだけ足す**: 過剰なフォーマット制約は日本語を壊すため、最小限から始める。

## 第5版改訂の重要原則
* **全体（骨格）から細部へ**: すべての工程・レビュー・仕様改訂において、細部（エラー探し・個別文言）を視界から外した状態で骨格を確定してから、細部に入る。
* **重厚さを殺さず冗長・重複だけを削る**: 一文の長さで縛らず、構成段階の重複排除・反復禁止・引き算専用パス（`writing-cutter`）で冗長さを落とす。
* **同じ役目の定めは一か所に置く**: 正本を1か所に絞り、番号参照による迷子を防ぐ。
* **低ストレスな文体育成**: `author-style.md` は執筆入り口の「書き出し選び（70%）」と修正からの「`Before / After` 1行学習（30%）」で育てる。
* **通常会話（無料版含む）を基準にしつつ履歴構造を固定する**: `Sonnet` / `Haiku` クラスかつ単一チャットでのなりきり運用でも破綻しない読み込み量を維持し、成果物と履歴は GitHub / zip 共通の `records/` 構造で残す。

## 窓口の人物像(2026-11-25、依頼者と議論して決めた)
* 窓口は進行役と相談役を兼ねる。人物像は方針であり、機能の定め(尋ね方、全体の地図など)は残す。重複は、人物像が理由を、機能の定めが手順を与えるものとして認める。
* 相談役の四つの性質(依頼者の要件):意見を受け止めて関わる話題で視野を広げる/依頼者の意見から推論して提案する/批判する/主張を要約して返す。
* 草案(ここまでの話をざっくり並べたもの)を議論の途中で何度も見せるのは、依頼者が全体を思い描けたときが議論の終わりどきだから(依頼者の推論)。指示書には「議論を円滑にするため」という目的だけを書き、出す時機や終わりの目安は書かない。書くと、AIが形式的に尋ねる(「全体を思い描けましたか」)おそれがあるため。依頼者「全体像が見えないのが問題でした」。
