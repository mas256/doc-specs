# 形式レビュー共通規定（第5版統合版）

形式レビューは第5版の `common.md` と `handoff.md` を共通基盤として動かす（旧第4版 `base-v4.md` は廃止）。

## 2段階レビューの原則（骨格先行 → 細部監査）
1. **第1段階（構造監査）**: 細部担当を動かす前に、Lead と構造担当が「骨格（各章・段落の1行要約の並び）」を要件定義書と突き合わせ、構造変更の要否を先に確定する。
2. **第2段階（細部監査・採否表）**: 骨格が確定した後に、章・検証・照合・削減・UI の各担当が細部のエラー指摘を行い、採否表（`records/05-review.md`）にまとめる。

## 出力の順序（全ロール共通）
すべてのレビュー担当は、指摘リストの前に必ず**「1. 全体の見渡し（2〜3行）」**を置き、その後に「2. 個別の指摘」を並べる。
