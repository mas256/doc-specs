# 指示書の点検(第5版、main 98f4583。経緯を知らない立場から)

点検の担当(opus、effort high。経緯の記録は渡していない)の報告。担当の Write が拒まれたため、担当が返した本文を窓口がそのまま保存した(2026-11-19)。

## 最も影響の大きい問題

1. 「全部任せる」と言われても一周できない。承認の関門と、各段の終わり方は、どれも依頼者の発言を条件にしている。「任せる」と言われたときに窓口が推奨案で決めて進む定めも、読んで直すをAIだけで終える条件もない(N7.5、N6.1、Z4.2、YN4.1、YN5.1)。
2. 段階の印の定め(N6.5・N7.5)では、「確認待ち」の発言にはいつも承認の形を付ける。一方、壁打ちでは問いを絞らない(Z1.2)。この二つがぶつかり、壁打ちの毎回の問いが「(a)/(b) から選ぶ」形に押し込まれる。
3. 窓口の仕事が、窓口が読むと書かれていない段のファイルにある(phase-2 の Z5.3・Z5.4、phase-3 の O4.2・O4.3)。START の A の行は、論点案と構成案について「企画の担当を起動する」としか書いていない。そのため、窓口がロールモデルの担当と検証担当を起動する手順と、依頼者の答えを写す手順を知らないまま進むおそれがある。

### (2) 依頼者が「全部任せる」と言い、AIだけで一周する

前提:題材は (1) と同じ(高校生向け、確率の直感がずれやすい話、800字の小論)とし、依頼者は全部任せて議論にも加わらないと言ったものとする。

結論:文面どおりには一周できない。最初に止まるのは、壁打ちを終えた後の承認(Z4.2・R4.3)である。

1. START 1:A として読む(全部任せて始める依頼は表の例にないが、A に最も近い)。
2. Z1.0:最初の発言で、依頼者が終えると言うまで壁打ちを続けると伝える定めである。依頼者が議論に加わらないので、この伝え方がそもそも合わない。Z4.2 の、壁打ちを任された場合の定めを使う。
3. 読者・読後に期待すること・切り口:N1.18 は、読後に期待することを依頼者が決めるとし、W1.2 は、依頼者が決める場所をAIの案で埋めないとしている。一方、方針と W1.3 は、任された事項はAIが決めるとしている。どちらを優先するかが書かれていないので、AIの判断が割れる(番号1)。ここでは、方針に従ってAIが人物像を作り、要件定義書と author-style を作るものとする。
4. 最初の停止(文面が止めている):Z4.2・R4.3 は承認を求めるとしており、N7.5 では承認されるまで案である。「任せる」を承認と見なす定めがない(番号1)。
5. 仮に「任せる」を承認と読んで進めても、各段で同じ形の停止が続く。
   - 論点案:Z5.4「依頼者が選び、承認する」。
   - 構成案:O4.2「依頼者は並べ方を選ぶ」。
   - 執筆:N6.1 の終わり方が「依頼者が書き終えたと言う」。
   - 【要確認】:M5.2 では、「依頼者の答え」は窓口が書き込む。依頼者がいないとき誰が答えるかについて、文面は何も言っていない。W5.5 によれば、答えを得るまで、それに依存する作業は進めない。
6. 読んで直す:どれを直すか、どこへ戻るか、誰が直すか(YN4.1)、依頼者が直すかAIが直すか(YN5.1)は、どれも依頼者が決める。終わり方は依頼者が終えると言うまで繰り返すことだけで、AIの側で終える条件について文面は何も言っていない。YN5.3 で直した箇所を読み直すたびに新しい弱いところが出うるので、やめる根拠がない(番号1)。
